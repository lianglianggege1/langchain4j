核心 API

Planner 接口（规划器要实现的）

init(ctx)
一次性初始化。GOAP：取 plannerAgent().outputKey() 为目标 + 建图
firstAction(ctx)
每轮执行起点。GOAP：跑图搜索，返回 call(path[0])
nextAction(ctx)
每个 agent 完成后回调。GOAP：游标 cursor++；越界则 done()
executionState() / restoreExecutionState(state)
崩溃恢复状态。GOAP：均为空——故意无状态
topology()
GOAP 返回 SEQUENCE（线性路径）

Action 类型（规划器的回答）

call(agents...)
执行这些 agent；多个则并行（CompletableFuture）。GOAP 每次只给 1 个
done() / done(result)
结束；结果默认从 scope 的 outputKey 读
suspend()
挂起系统，落检查点，释放调用线程
noOp()
空转一步（等待外部事件时用）

依赖图构建规则（GoalOrientedSearchGraph）

概念来源writer 实例对应
节点agent 输入参数名（@V）或 outputKeytopic / style / audience / story / styledStory / finalStory
边每个 subAgent：每个输入节点 → 输出节点storyGenerator、styleReviewLoop、audienceEditor 各自的 输入→输出
入图范围仅 planner 直接注册的 subAgents循环内部的 styleEditor / styleScorer 不入图
前置条件搜索时 scope 现有 key 集合；图中不存在的 key 被过滤丢弃{topic, style, audience}（additionalKey 被滤掉）
目标规划根代理的 outputKeyfinalStory

搜索算法（DependencyGraphSearch：改造版 A*）

  • 状态 = 已激活节点集合（SearchState）
  • 可激活判定 = 该节点全部输入依赖已在激活集合中
  • 启发函数 h = 从目标向下 BFS 收集的未激活节点数（可采纳，不高估）
  • 单步代价 g = 1.0（每激活一个节点）
  • f = g + h，PriorityQueue 弹出最小 f
  • 终点 = 当前节点 == goal，cameFrom 回溯重构激活序列

节点路径 → agent 路径（search 后半段）：

  • 遍历节点路径，跳过 precondition 节点
  • 对其余节点，从后向前找有边相连的 agent（edges.get(NodePair(前, 当前))）
  • 找不到边 → 抛 IllegalStateException("No path found for node: …")
  • 结果打日志：Agents path sequence: [storyGenerator, styleReviewLoop, audienceEditor]

运行时循环（PlannerLoop）六步

  1. writeAgenticScope()：方法参数写入黑板
  2. （若有）恢复执行状态 + 已完成 agent 集合
  3. firstAction() → 进入 while (!isDone())
  4. AgentCallAction：1 个 agent 顺序执行；多个 CompletableFuture 并行
  5. agent 完成回调 onSubagentInvoked()：saveExecutionState()（GOAP 为空）+ agenticScope.checkpoint()，再 nextAction()
  6. done() → result()：有 outputKey 则 readState(outputKey) 返回

常见坑

坑真相
以为要持久化规划进度GOAP 靠「重搜」自愈：恢复时已完成输出在 scope 里，路径自动变短；持久化游标反而可能越界
scope 多了脏 key 怕影响规划非图中 key 会被 filter(Objects::nonNull) 静默过滤
以为循环内 agent 参与顶层规划循环对 GOAP 是单个动作（接口方法参数=前置条件，builder 的 outputKey=效果）
多个 agent 塞进一个 call() 想「让 GOAP 并行」并行通道在运行时（PlannerLoop），但 GOAP 的 A* 只产出线性序列；要并行用 ParallelPlanner
找不到路径firstAction 抛 IllegalStateException("No path found for goal: …")——检查某 agent 的 @V 名字 / outputKey 是否拼错（图就是靠这些字符串连起来的）
