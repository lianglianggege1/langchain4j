Voting 模式速查表

langchain4j-agentic-patterns · VotingPlanner / VotingStrategy · 一句话：并行扇出全部投票者，票齐后聚合收敛。

一图流

VotingPlanner 决策逻辑（全文逻辑，5 条）

  1. init()：拿到投票者名单（subAgents）。
  2. firstAction()：名单为空 → done；否则 call(全部投票者) —— 并行的唯一声明。
  3. nextAction()（每个 agent 完成时被回调，持锁）：票箱 add 该 agent 的返回值，计数 +1。
  4. 计数 < 名单数 → noOp()（等待占位）。
  5. 计数 == 名单数 → done(strategy.aggregate(votes))；聚合值随后被写进 outputKey 并作为返回值。

VotingStrategy（聚合函数）

策略语义票型要求经典对照
majority()分组计数取众数任意（靠 equals 分组）随机森林表决
average()数值均值Number回归集成
highest()取 Comparable 最大Comparable乐观边界
自定义 lambda任意收敛函数看实现critic 的「评审团合议」

两个实例的组装配方

classifier（纯表决）

// 投票者：同一输入、不同人设 prompt
c1 = agentBuilder(C1.class).outputKey("vote1")…
c2 = agentBuilder(C2.class).outputKey("vote2")…
c3 = agentBuilder(C3.class).outputKey("vote3")…

voter = plannerBuilder(Voter.class)
    .subAgents(c1, c2, c3)
    .outputKey("classification")
    .planner(VotingPlanner::new)   // majority
    .build();

断言：result == "POSITIVE"（2:1 表决通过）。

critic（嵌套复合）

votingCritics = plannerBuilder()          // 无类型
    .subAgents(styleC, origC, engageC)
    .outputKey("critique")
    .planner(() -> new VotingPlanner(
        critiquesAggregator()))      // 均值+拼接
    .name("votingCritics").build();

storyEditor = agentBuilder(…)
    .chatModel(scope -> score > 7.8
        ? enhancedModel() : baseModel()) // 动态选模型
    .outputKey("story").build();

reviewLoop = loopBuilder()
    .subAgents(votingCritics, storyEditor)
    .maxIterations(5)
    .exitCondition(s -> score >= 8.5)
    .outputKey("story").build();

evaluator = sequenceBuilder(E.class)
    .subAgents(writer, reviewLoop)
    .output(scope -> ScoredStory(…)).build();

运行时要点（对照 PlannerLoop）

  • 并行机制 = 一个 Action 装 N 个 agent → parallelExecution()（CompletableFuture.allOf）
  • 收票在 agent 完成回调 onSubagentInvoked() 中，ReentrantLock 串行化 → votes 线程安全
  • 票源 = previousAgentInvocation().output()（返回值），不是黑板 state
  • 中间的 noOp 会被 composeActions 吞掉；最后一张票带来 done(aggregate)
  • topology() = PARALLEL（元数据声明；真正的并行来自 call 的多 agent 语义）
  • 聚合值经 result() 写入 outputKey（classification / critique）

坑位清单

坑说明 / 对策
平票不确定majority 遇 N 个互异答案时计数全为 1，取 HashMap 遍历首个最大——需自定义加权策略
格式漂移毁表决"POSITIVE" vs "Positive." 是不同的票；用 prompt 约定格式，或在聚合器里先 normalize
投票者同质化相同 prompt × N = 三倍成本一份答案；多样性（人设/模型/温度）才是投票的价值来源
挂起恢复会坏votes/completedCount 不持久化；部分完成后恢复 → filterCompletedAgents 剔除已完成者，计数永远凑不齐 → noOp 空转（活锁）。短任务用没问题
outputKey 冲突票本身不依赖黑板，但每人独立 outputKey 才有留痕可审计；聚合值占规划根的 outputKey

与其他模式的关系

模式收敛机制一句话区别
Voting聚合函数（一次收敛）各投一票，静默聚合
Debate多轮互相说服先吵起来，吵完再收敛
Blackboard无显式聚合各方自由写黑板，无收敛函数
GOAP不聚合搜索顺序，单路径执行
Loop（子组件）退出条件常与 Voting 组合：vote → 改进 → 再 vote
